# Salesforce Practical Master Guide

## Purpose of this Guide

This guide helps you understand how to build ANY simple Salesforce management system step-by-step for practical exams.

No matter what system comes in exam:

* Banking System
* Hospital Management
* Student Management
* Event Management
* Library Management
* Hotel Management
* Inventory Management
* Employee Management

The logic remains almost the same.

---

# Core Understanding

Every Salesforce practical project mainly contains:

1. Objects
2. Fields
3. Relationships
4. Flow Automation
5. Reports

If you understand these 5 things, you can build almost any project.

---

# STEP 1 — Understand the Scenario

First ask yourself:

## What are the MAIN entities?

Example:

### Banking System

* Customer
* Transaction

### Hospital Management

* Patient
* Doctor
* Appointment

### Student Management

* Student
* Course
* Enrollment

### Event Management

* Event
* Participant
* Registration

These entities become OBJECTS.

---

# STEP 2 — Create Objects

## What is an Object?

Object = Database table.

Every object stores a specific type of information.

---

# Generic Steps to Create Object

1. Setup
2. Object Manager
3. Create → Custom Object
4. Fill:

   * Label
   * Plural Label
   * Record Name
5. Enable:

   * Allow Reports
   * Allow Activities
6. Deployment Status → Deployed
7. Save

---

# STEP 3 — Add Fields

## What are Fields?

Fields store data.

Examples:

* Name
* Age
* Balance
* Date
* Status
* Amount

Used for:

* Name

* Location

## Number

Used for:

* Age

* Duration

## Phone

Used for:

* Contact number

## Email

Used for:

* Email IDs

## Date

Used for:

* Appointment date

* Registration date

## Picklist

Used for fixed options.

Example:

* Status
* Type

---

# STEP 4 — Understand Relationships

## Why relationships are needed?

To connect objects.

Example:

Appointment connects:

* Patient
* Doctor

Enrollment connects:

* Student
* Course

Registration connects:

* Event
* Participant

---

# Most Important Relationship

## Lookup Relationship

This is the easiest and most used relationship.

### Steps:

1. Open child object
2. Fields & Relationships
3. New
4. Lookup Relationship
5. Select parent object
6. Save

---

# How to Identify Parent and Child?

## Parent = Main entity

## Child = Connecting entity

Example:

Enrollment:

* Student lookup
* Course lookup

So Enrollment becomes bridge object.

---

# STEP 5 — Create Tabs

Sometimes object does not appear in App Launcher.

### Steps:

1. Open object
2. Tabs
3. New
4. Choose icon/style
5. Save

---

# STEP 6 — Create Flow Automation

## What is Flow?

Flow automates tasks.

Example:

* Update balance automatically
* Set status automatically
* Update counts

---

# Most Common Flow Type

## Record-Triggered Flow

Runs automatically when record is created.

---

# Generic Flow Creation Steps

1. Setup
2. Flows
3. New Flow
4. Record-Triggered Flow
5. Select Object
6. Trigger = Record Created
7. Optimize = Actions and Related Records
8. Done

---

# Simplest Automation

Automatically set Status.

Examples:

* Appointment → Scheduled
* Registration → Registered
* Enrollment → Enrolled

---

# Generic Update Records Logic

1. Add Update Records
2. Specify conditions
3. Object = same object
4. Condition:

   * Record ID = $Record.Record ID
5. Set Field Values:

   * Status = value
6. Save
7. Activate Flow

---

# Banking System Special Logic

Banking system usually needs:

* Deposit
* Withdraw

This requires calculations.

---

# Banking Flow Logic

## Deposit

New Balance = Old Balance + Amount

## Withdraw

New Balance = Old Balance - Amount

---

# Common Flow Elements

## Decision

Used to check conditions.

Example:

* Deposit?
* Withdraw?

---

## Get Records

Fetches related record.

Example:

* Get Customer
* Get Patient
* Get Student

---

## Assignment

Used for calculations.

Example:

* Balance = Balance + Amount

---

## Update Records

Used to save changes.

# Final Tip

Almost every management system follows this pattern:

Main Object A ← Bridge Object → Main Object B

Examples:

Customer ← Transaction → Banking
Student ← Enrollment → Course
Patient ← Appointment → Doctor
Participant ← Registration → Event

Once you understand this pattern, you can build any simple Salesforce project.
